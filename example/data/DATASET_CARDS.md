## 6. 함정·주의 (전부 실측 확인)

1. **[치명] 10C 시험 실패 7셀이 NaN이 아니다.** `grav_dis_10c_mahg`가 **0.0009 mAh/g** 수준(실질 0)이라 `dropna()`로 걸러지지 않는다. 해당 셀: **DD027, DD028, DD059, DD051, DD029, DD030, DD031** — 7셀 전부 `density_level='P'` 이고 전부 `coat_weight_level='H'`.

2. **[치명] 이상치가 상관계수 부호를 뒤집는다.** 공극률 vs 10C 그램당용량 Pearson:
   - 전체 54셀: **−0.1154**
   - 10C 실패 7셀 제외 (n=47): **+0.0812** → **부호 반전**
   "상관계수 하나로 결론 내지 마라"의 실증 사례.

3. **[치명] 캘린더링 날짜와 롤온도가 완전 교락.** 교차표 실측:
   `2021-10-15 → 85°C (6조건)` / `2021-10-18 → 120°C (6조건)` / `2021-10-27 → 145°C (6조건)`.
   1:1 대응이므로 **온도 효과와 날짜(로트·습도) 효과를 이 데이터만으로 분리 불가**.

4. **[치명] 캘린더링 전 물성은 코팅중량과 완전 공선.** 18조건에 값이 2개뿐 —
   `precal_grad_carbon` H=0.01758 / L=0.00654 · `precal_moran_carbon` H=0.646 / L=0.605 · `precal_tensile_strength_kpa` H=683.25 / L=728.62.
   **예측변수로 넣으면 안 된다.** (좋은 다중공선성 실습 재료)

5. **충방전기 장비가 조건과 부분 교락.** 교차표 실측: **BCS7 = L 11셀 / H 0셀**, **BCS8 = H 11셀 / L 1셀**, BCS3 = H 8 / L 11. 장비 효과와 코팅중량 효과가 섞여 있다.

6. **[신규 발견] 공극률 측정치가 파일마다 다르다.** `wmg_cells_54.csv`의 `porosity_pct`(하프셀 워크북 유래)와 `wmg_conditions_18.csv`의 `cal_porosity_pct`(캘린더링 워크북 유래)는 같은 조건인데 **최대 2.57 %p 차이**가 난다. 목표 대비 오차도 어느 쪽을 쓰느냐에 따라 **부호가 바뀐다**:

   | | 셀 단위 `porosity_pct` 기준 | 조건 단위 `cal_porosity_pct` 기준 |
   |---|---:|---:|
   | H_P / H_M / H_D | **−0.41 / −0.24 / +1.06** | +0.30 / +0.94 / +1.72 |
   | L_P / L_M / L_D | +1.24 / +1.02 / +1.56 | +0.72 / +1.67 / +2.85 |

   → **어느 컬럼을 썼는지 반드시 명시**할 것. 교재 본문에 수치를 실을 때 출처 컬럼을 병기해야 한다.

7. **원본 자체의 계산 오류.** DD001은 C/20 충전용량이 빈칸인데 그램당·부피당 충전용량 칸에 **0**이 기입돼 있어, 원본 워크북 Mean이 `(0+182.9111+183.0876)/3 = 121.9996`(참값 약 183)으로 오염돼 있다. → **가공본은 이 0을 결측으로 되돌렸고, 원본의 Mean·SD 열은 일절 사용하지 않았다.** "남이 계산해 준 평균을 믿지 마라"가 숫자로 증명되는 사례.

8. **결측 내역 (총 14건, `wmg_cells_54.csv`)**: `v_after_assembly_v` 3건(DD034/035/046) · `first_cycle_loss_pct` 1건(DD001) · ASI 6열 각 1건(DD020) · `cyc_*` 4열 각 1건(DD059).
   ※ DD059의 사이클 데이터는 `wmg_cycling_long.csv`에 **존재하므로 복구 가능**.
   ※ `wmg_cycling_long.csv` 결측 270건 = `cap_chg_mah` cycle 0에서 54건(원본 주석 "이전 사이클 불완전 방전으로 부정확") + `retention_pct`·`coulombic_eff_pct` 각 108건(= 54셀 × cycle 0·51, 원본이 cycle 1~50만 제공).

9. **`n_passes`는 설계값이 아니라 결과값**(목표밀도 도달까지 반복 통과). X에 넣을 때 인과 해석 주의.

10. **레이트 시험에서 충전은 항상 고정, 방전만 변한다.** 실측 스텝 구조: step 1 = C/20 충·방전 → step 2~7 = C/5 충·방전 → **step 8~12 = 충전 C/5 고정, 방전만 C/2 → 1C → 2C → 5C → 10C**. 원본 충전용량 행 라벨이 전부 'At C/5'라 혼동하기 쉬워 `wmg_rate_long.csv`에서 `charge_c_rate` / `discharge_c_rate`로 분리해 두었다.

11. **[의미 확인불가] ASI의 2차 '0.5'·'0.2' 라벨.** 원본에 설명이 전혀 없다. `soc_fraction` 0.2와 0.5만 `occurrence=2`가 추가로 존재하며(각 54건) 값도 다르다(DD001 기준 0.5 → 52.58 vs 43.63). **무엇인지 모르겠음.** `occurrence=1`만 사용 권장.
    또한 라벨 0.9~0.1이 **SOC인지 DOD인지도 원본에 정의가 없어** '상태 분율'로만 기술했다.

12. **용량유지율 100% 초과가 54셀 중 31셀(총 315행)** 에서 발생. 초기 젖음/활성화로 실제 나타나지만 DD021은 101.5%까지 튀고 쿨롱효율이 66~91%로 요동친다(전체 중앙값 99.04%).

13. **물리적 불가능 값**: DD020의 `grav_dis_c20_mahg` = **226.80 mAh/g**. NMC622의 4.2V 실용용량(약 165~180)을 크게 초과. 같은 셀의 ASI도 전부 결측이다.

## 6. 함정·주의 (전부 실측 확인)

1. **[치명] 데이터 누수는 프레임이 아니라 "영상"에서 터진다.**
   32×32 그레이스케일 + RandomForest(120 trees) 5-fold AUC 실측:

   | 대상 | 랜덤 KFold | GroupKFold(**frame**) | GroupKFold(**video**) |
   |---|---:|---:|---:|
   | Surface_Crack | 0.896 | 0.907 | **0.702** |
   | Pinhole | 0.701 | 0.712 | **0.487** |

   프레임 단위로 묶어도 성능이 안 떨어진다(패치가 3×3로 공간 분리돼 있어서). 그러나 **영상 단위로 묶으면 Pinhole은 AUC 0.49 = 무작위 수준까지 붕괴**한다. 모델이 결함이 아니라 그 영상의 조명·배경을 외우고 있었다는 뜻.
   → **"group 컬럼만 넣으면 안전"이 아니라 "어느 수준의 group이냐"가 핵심.** `group_frame`과 `video_id` 두 컬럼을 다 제공한 이유다.

2. **[치명] 코팅갭 효과와 영상이 완전 교락.** 갭 1수준당 영상이 1~2개뿐이라 갭 효과와 영상 효과를 분리할 수 없다. **갭-결함률 표를 인과로 읽으면 안 된다.**

   | 갭(µm) | 패치수 | Surface_Crack | Delamination | Pinhole | unclassified |
   |---:|---:|---:|---:|---:|---:|
   | 600 | 306 | 59.2% | 0.0% | 38.2% | 10.1% |
   | 700 | 407 | 82.8% | 10.8% | 24.3% | 4.4% |
   | 800 | 303 | 81.5% | 16.5% | 28.4% | 2.6% |
   | 900 | 304 | 95.7% | 1.6% | 12.8% | 4.3% |
   | 1000 | 230 | 98.3% | 9.1% | 20.9% | 0.9% |
   | 1100 | 677 | 98.2% | 12.3% | 19.2% | 0.9% |

   **결정적 반례**: 같은 700 µm인데 런이 다르면 Delamination이 **R1 0.36% vs R7 32.58%**. "상관 ≠ 인과"를 현장 데이터로 가르치기 좋다.

3. **라벨이 하나도 없는 44장.** 이들의 마스크는 **전부 빈 마스크**(44/44 교차 일치). "정상"인지 "미라벨"인지 **원본에 정의가 없다.**

4. **세 과제의 대상이 다르다.**
   - 검출 박스는 **Pinhole·unclassified 에만** 존재. Surface_Crack·Delamination에는 없다.
   - 분할 마스크는 **클래스 구분 없는 이진 마스크**(0/255).
   - 빈 마스크 81장 = 무라벨 44장 + **unclassified 단독 37장**(실측 교차 확인). 즉 unclassified 78장 중 37장은 마스크가 비어 분할 학습에 쓸 수 없다.

5. **[추론값] YOLO 클래스 이름은 원저자 정의가 아니다.** 원본에 `data.yaml`·`classes.txt`가 없다. 실측 교차검증으로 **추론**: id 0 ↔ Pinhole 양성 519장과 정확히 1:1, id 1 ↔ unclassified 양성 78장과 정확히 1:1, 불일치 0건. txt가 없는 1,646장의 Pinhole·unclassified 양성률은 정확히 0.000. **근거는 매우 강하나 공식 정의는 확인불가.**

6. **큐레이션 54장 중 1장**은 프레임 중복 없이 6장을 못 채워 프레임 재사용 완화 규칙이 적용됐다(`pick_reason`에 `unique_frame=False` 기록). 나머지 53장은 서로 다른 프레임.

7. **`label_combo`는 반드시 문자열.** `'0010'` 형태로 저장하면 `read_csv`가 정수 10으로 바꿔 앞자리 0이 사라진다. 하이픈 연결(`'0-0-1-0'`)로 항상 str로 읽히게 했다(실측 dtype `str` 확인).

## 6. 함정·주의 (전부 실측 확인)

1. **[치명] `label` 부호가 직관과 반대다.** **−1이 정상, 1이 불량.** 수강생이 가장 많이 틀리는 지점이라 `fail`(0/1) 파생 컬럼을 별도 제공했다.

2. **[치명] 이차전지 메인 실습으로 쓰면 안 되는 3가지 근거**:
   - **공정이 다르다**: 반도체 전공정(웨이퍼 단위 포토·식각·증착) 데이터임이 `secom.names`에 명시. 이차전지의 전극 코팅·압연·조립·화성(formation) 공정과 **물리적 대응 관계가 없다.** 수강생이 "우리 공정"으로 오인하면 **잘못된 도메인 직관**이 생긴다.
   - **품질 정의가 다르다**: SECOM 라벨은 라인 내 검사 **단일 Pass/Fail 이진값**. 이차전지 품질은 용량·내부저항·자가방전·수명 등 **연속형 다중 지표**이며 불량 판정도 화성 공정 이후 **시간 지연**을 두고 나온다. 이진 분류 하나로 환원되지 않는다.
   - **센서 해석이 불가능하다**: 익명화되어 있어 공정 엔지니어가 **자기 도메인 지식을 투입할 여지가 전혀 없다.** 이 교재의 대상은 "도메인 지식은 있고 코딩만 없는" 공정 엔지니어이므로 주교재로 부적합.

3. **[치명] `dropna()` 금지.** 결측 0인 행이 **0개**라 그대로 쓰면 데이터가 전멸한다.

4. **문서-실물 불일치**: `secom.names`와 UCI 페이지는 **"Number of Attributes: 591"** 이라 적었으나 실제 `secom.data`는 **590열**이다(1,567줄 전수 토큰 카운트로 확인. 591은 라벨 포함 수로 판단). → **"문서를 믿지 말고 `df.shape`를 찍어라"** 를 가르칠 실물 교보재.

5. **중복 `timestamp` 33건** → **timestamp를 인덱스·키로 쓰면 안 된다.**

6. **성능 기대치 관리**: `secom.names`의 베이스라인 BER 33~40%는 **거의 무작위에 가까운 성능**이다. 이 데이터로 높은 성능이 나왔다면 **누수를 의심**해야 한다. 과도한 기대를 심지 말 것.

7. **2008년 데이터로 현재 공정 수준을 대표하지 않는다.**

8. **용량 주의**: 배포 폴더 **9.70 MiB** 로 5개 데이터셋 중 최대. `secom_clean.csv`(4.59 MB)는 `secom_merged.csv` + `secom_column_report.csv`의 `drop_reason`으로 **한 줄에 재현 가능**하므로, 용량을 줄여야 하면 삭제해도 무방하다(그 경우 `README.md` 파일 구성 표도 함께 수정 필요).

## A-7-6. 작업 중 발생한 사고·복구 이력 (투명 보고)

1. **WMG**: 작업 시작 시점에 스크래치패드에 동일 ZIP과 압축해제본이 이미 존재했다(선행 시도 흔적). **SHA-256이 Mendeley API 게시 해시와 일치하여 진본 확인.** 배포용 엑셀은 그 ZIP에서 직접 재추출한 것을 사용. 배포 폴더의 빈 폴더 `raw_xlsx`(선행 시도 잔여물)는 제거했다.

2. **EIS**: 이전 세션 산출물 3개(`eis_long.csv` / `eis_wide.csv` / `eis_data_dictionary.csv`)를 **덮어썼고 백업하지 않았다(복구 불가).** 스키마가 대문자 → 소문자, `ZRE_0_05Hz` → `Zre_0.05Hz`로 바뀌었다. **이전 스키마를 참조한 원고·코드가 있다면 전량 갱신 필요.** 이전 산출물의 좋은 아이디어 2개(`repeat_id`, `-Im{Z}` 컬럼)는 현재 버전에 흡수했다.

3. **SECOM**: 배포 폴더에 이전 세션 산출물이 존재했고 일부를 덮어써 README 기재 스펙과 어긋났다. `prepare.py`를 재작성해 3개 산출물을 전량 재생성하여 정합성을 복구했다. **이전 `prepare.py` 원본은 덮어쓰기로 복구 불가.** 다만 재생성된 `secom_column_report.csv`가 이전 파일과 **34,880 B로 바이트 크기까지 동일**해 산출 로직이 동등함을 확인했다. 파일 크기 변경(merged 5,747,991 → 5,309,713 B, clean 4,886,314 → 4,809,980 B)은 센서 값을 float 재포맷 대신 **원본 텍스트 토큰 그대로 기록**했기 때문이며, 그 결과 원본과 값이 정확히 일치함을 `array_equal`로 검증했다.

4. **RUL**: 산출 폴더에 이전 실행의 잔여 파일 2개(`Battery_RUL.csv`, `battery_rul_full.csv`)가 존재. **데이터 삭제는 임의로 하지 않았다.** 중복 여부는 SHA-256과 전 행 수치 비교로 확인 완료 (A-6-3).

5. **CoatingVision**: `label_combo`를 `'0010'` 문자열로 두면 `read_csv`가 정수 10으로 바꿔 앞자리 0이 사라지는 문제, 그리고 detection 라벨 없음을 빈 문자열로 두어 NaN 1,646개가 생기는 문제를 **가공 중 발견해 수정**했다(하이픈 연결 / `'none'` 채움). 현재 결측 0.

6. **다운로드·가공 단계에서 최종 실패한 작업은 없다.** 5개 데이터셋 전부 다운로드·파싱·검증 성공. (SECOM에서 curl exit 43이 1회 발생했으나 Python urllib로 전환해 HTTP 200 정상 수신, 최종 결과 영향 없음.)
